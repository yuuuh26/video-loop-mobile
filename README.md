# VIDEO LOOP Mobile

スマホ内の短い動画を、1本ずっと、または指定回数ずつ順番にリピートする個人用PWA。Android Chromeを主対象にした、ビルド不要のHTML・CSS・JavaScriptアプリです。

## 使い方

1. GitHub Pagesの公開URLをChromeで開きます。
2. 「動画を追加」で動画を複数選び、「端末に保存済み」の表示を確認します。
3. 「1本をずっと」または「回数で次へ」を選びます。回数は初回を含む総再生回数です。
4. 再生ボタンをタップします。回数モードでは最後の動画の次に最初へ戻ります。
5. Chromeメニューの「ホーム画面に追加」または「アプリをインストール」から追加できます。

最初はMP4（H.264/AAC）を使って確認してください。すべてのMP4やHEVC等への対応は保証しません。アプリを他の画面へ切り替えると停止し、戻ったらタップで再開します。

## 保存とプライバシー

動画・ファイル名・順番・設定を外部へ送信する機能はありません。IndexedDBへ動画のコピーを保存し、Blob URLで再生します。広告、解析、CDN、外部APIは使用しません。CSPでも通信を制限しています。

アプリ本体の初回読み込みと更新はGitHubへ通信します。GitHub Pagesへのアクセス時はGitHub側にIPアドレスが記録されます。動画ファイルのアップロードとは別です。

元動画はスマホに残してください。Chromeのサイトデータを消すと、アプリ内の動画コピーも消えることがあります。アプリ内の削除は元動画を削除しません。永続ストレージの許可は、サイトデータの手動削除まで防ぐものではありません。

同じ `https://ユーザー名.github.io` 配下のアプリは同じオリジンです。DB名やリポジトリ名の違いは完全なアクセス分離にはなりません。自作アプリは信頼できるコードだけで運用してください。独自の動画暗号化やロックはありません。

## 設定バックアップ

設定画面からJSONを出力・復元できます。JSONには動画本体を含みません。復元先にも元動画を追加し、表示された候補や割り当てを確認して復元します。同名・同サイズの候補が複数ある場合は、自動確定せず選び直せます。

## GitHub Pagesへ公開

リポジトリ名は **video-loop-mobile** にしてください。別の名前にする場合は `manifest.webmanifest` の `id`・`start_url`・`scope` の3か所を変更します。既存PWAと同じIDを使わないでください。

1. 自分のGitHubに `video-loop-mobile` というPublicリポジトリを作成します。
2. このパッケージの中身をリポジトリ直下へ配置します。`index.html` がフォルダの中にもう一段入らないようにします。
3. リポジトリの **Settings → Pages** を開き、**Deploy from a branch → main → /(root) → Save** を選びます。
4. `https://ユーザー名.github.io/video-loop-mobile/` で起動を確認します。

動画ファイル・私的なJSONバックアップをリポジトリへ入れないでください。`.gitignore` でも主要な動画拡張子を除外しています。

## ファイル構成と保守

- `index.html` / `style.css`：スマホ用の画面
- `app.js`：操作、設定、Wake Lock、復元、PWA起動
- `player.js`：動画の再生と回数切り替え
- `storage.js`：IndexedDBと動画の確認
- `backup.js`：設定バックアップの検証・照合
- `sw.js`：自アプリの資産だけをキャッシュするService Worker
- `manifest.webmanifest` / `icons/`：固有のPWA設定とPNGアイコン
- `tests/`：再生競合、回数、バックアップ、保存結果、キャッシュ分離の自動確認

アプリ更新時は表示版・`package.json`・`sw.js`のキャッシュ版を整合させます。保存DBを削除せず、必要なデータ移行を用意してください。新しいService Workerが待機した場合は、設定画面の更新ボタンで再生を止めて切り替えられます。

## 検証

Node.jsで `npm test` と `npm run check` を実行できます。アプリ本体にnpm依存はありません。

この制作環境での確認結果と、Android実機で必要な確認は `VALIDATION.md` を参照してください。自動テストは模擬した動画要素のイベントを使うため、実機デコードやバッテリー制御を確認するものではありません。
